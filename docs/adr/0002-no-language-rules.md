# The kit carries no language rules

Per-language lint, type-check, docstring, and coverage enforcement lives in the full-lint reference repo, applied per project by the `init-<lang>-repo` skills it ships. The kit keeps only language-agnostic conventions (comment-style, code-organization, minimal-changes, look-it-up, and so on). The kit previously carried the Python stack (`python`, `python-pytest`, `python-class-sections`, `python-docstrings-google`) and later also Django process rules (`django-migrations`, `engineering`); the owner works in whatever language a project needs and already maintained the stricter stack in the reference repo, so kit copies were redundant and guaranteed to drift. Work-stack process rules left with the work stack itself (see ADR-0003, superseded by ADR-0007).
