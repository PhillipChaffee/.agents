# pstack is ported into the kit as harness-, model-, and forge-neutral skills

The kit carries a port of [pstack](https://github.com/cursor/plugins/tree/main/pstack) (Lauren Tan, MIT, imported at 0.15.32): `poteto-mode` and its 23 playbooks, 24 one-principle skills, the situational skills around them, and the `poteto-agent` and `comment-sicko` subagents. The upstream plugin is written for Cursor, pins Grok and Claude model slugs per role, and drives GitHub through `gh`, Graphite, and Cursor's Origin. The port keeps every skill's steps and voice and changes only the spans that carry one of those three dependencies: Cursor tool names, subagent fields, paths, and product features become a neutral vocabulary mapped per harness in `skills/poteto-mode/references/harness-adapter.md`; model slugs become named roles that resolve through the installer's `fast`/`main`/`deep` tiers and an optional `pstack-models` role file written by `/setup-pstack` (ADR-0001), defined in `references/model-roles.md`; `gh` and Origin commands become named forge operations resolved through the repo's `docs/agents/issue-tracker.md` (ADR-0007), defined in `references/forge-operations.md`. Skill names stay as upstream's so the pstack guide and its community references still apply; renaming is a directory move the owner can make later.

Not ported, each for one of the kit's existing decisions: `tdd` (the kit routes `/tdd` to the Matt Pocock skill, ADR-0004, and pstack's references now point there), `typescript-best-practices` (no language rules, ADR-0002), `make-bot-ui` (a Grok Bot and Tailscale product feature), the `benny` automation pack (Cursor Automations only), and the `watch-pr` and `orch` TypeScript tools (GitHub-bound and bun-built; the babysit and orchestrate playbooks describe the same loop over forge operations and plain store files). The node and shell scripts that are generic ship with their skills, so the installer now copies every file under a skill, not only markdown, and the validator refuses vendor model slugs, Cursor subagent fields, and forge CLIs in kit content. The port's first commit is a byte-for-byte import at the kit paths, and every wording change after it is its own commit, so any file can be diffed against or restored to upstream's text.
