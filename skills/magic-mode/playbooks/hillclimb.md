# Hillclimb

**You own the metric and the experiment's integrity. Supervise and review.** Delegate the attempts, and keep every heavy step a flat depth-1 wave. Each wave resolves its model from a role line in the `magic-models` role file.

For sustained, iterative improvement of one measurable thing against a target. A one-off fix is Bug fix or Perf issue. This is the loop.

Core discipline is one change, one measurement, keep or revert. Never stack untested changes, and never claim a win from code inspection (the **principle-prove-it-works** skill).

1. **Ground and arm.** Run the `how` skill over the target, name the realistic workload dimensions that can move the result (data size, history, state, concurrency), and select a case that reproduces the user's complaint. If no case reproduces it, fix the repro instead of hillclimbing. Then fix one metric, the direction that counts as better, and a checkable stop predicate that pairs a target with a floor on attempts so a lucky early win cannot end the run (the example "at least 50% better than baseline and at least 10 iterations" is this shape). Use the user's numbers when given, otherwise agree them.
2. **Wave 1, freeze the harness.** Dispatch one `magic-agent` on `hardest tasks` (default `deep`) with the workload, the metric, and the predicate. It builds the harness, proves its sensitivity on contrasting workloads, prints its error count and work count, and vets it with the **benchmark-checklist** skill before freezing it. One repeatable command then emits the metric, sampled enough to clear the noise (median of N, not a single run). It records the baseline metric and one green run of the regression gate before any change.
3. **Wave 2, ground hypotheses.** Dispatch one `magic-agent` on `judgment and prose` (default `deep`), or on `hardest tasks` for a gnarly mechanism, with the architecture model, the frozen harness output, and the plateau history. Every hypothesis names a specific mechanism ("defer X off the boot path because it blocks first paint"), never "try memoizing something". For a perf metric, order hypotheses by the performance mantras in step 2 of the Perf issue playbook (`playbooks/perf-issue.md`) and borrow only their order. The same wave proposes the plateau pivots from step 6 below.
4. Open the decision log via the **show-me-your-work** skill. A `decision.tsv` with one row per attempt, carrying id, hypothesis, change, before, after, delta, tests, verdict (kept or reverted), and note. Read it before each attempt. Keep it out of the tree (gitignored).
5. **Wave 3, the iteration.** One hypothesis per iteration. Dispatch a fresh `magic-agent` on the `hillclimb` line (default `main`) with the hypothesis, the file fence, and the frozen command. It implements the change, runs the frozen harness and the regression gate, and reports the metric. The leaf commits only when the metric moves past noise and the gate stays green, and reverts the change in full otherwise. This chat audits the reported metric and discards any commit that missed the bar. A tweak that "might help" is not kept. One commit per accepted fix, staging only the changed files (`git add <files>`, never `-A`). Log the row either way, kept or reverted. Each iteration ends in a check before the next begins, per **principle-sequence-verifiable-units**. Several independent hypotheses may fan out to parallel leaves at depth 1, each in its own worktree (the **principle-separate-before-serializing-shared-state** skill). If the run is unattended, borrow only the wake mechanism from the Autonomous run playbook (`playbooks/autonomous-run.md`), not its stop rule.
6. Push past the first plateau. On a stall or several rejects in a row, pivot category, combine near-misses, re-read the source, or try something more radical before concluding the hill is climbed. Correctness and simplicity outrank the number. Revert a win that breaks behavior, and keep a simplification that holds the number (the **principle-laziness-protocol** skill).
7. Stop when the predicate is met, or when the remaining ideas are marginal and not worth their cost. Don't relax the predicate to meet it, and don't quit while cheap untried hypotheses remain. Surface a genuine stuck state instead of spinning.
8. **Wave 4, open the PR.** Run **Opening a PR** with the accepted commits stacked in the order they landed. Its commit splitting, `/make-pr-easy-to-review`, PR body, and reply draft run in one `judgment and prose` (default `deep`) `magic-agent`.

**Reply.** Give the metric and target, baseline to final with the percent delta, iterations run (kept vs reverted), each accepted fix on one line, the `decision.tsv` path, and the best idea you would try next if pushed further.
