# Refactoring

**You own the contract. The structure changes. The behavior does not.** Distinct from Feature, which adds behavior, and Bug fix, which corrects it. Each heavy step is a flat depth-1 wave, and every wave takes its model from a role line in the `magic-models` role file.

If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to Feature. Large or cross-cutting structural work belongs to the **figure-it-out** skill. This playbook is the focused-to-medium change.

1. **Wave 1, learn the contract.** Run the `how` skill over the affected subsystem, then apply the **take-a-step-back** principle skill to confirm the requested refactor serves the user's goal and does not preserve or polish a broken mechanism.
2. **Wave 2, pin and shape.** Dispatch one `magic-agent` on the `feature, refactoring` line (default `main`) to write the characterization test, snapshot, or equivalence harness that captures current behavior before any structure moves. If the area has no coverage, this pin lands before anything else. Type check and lint are not a pin. When the target crosses a function boundary, run `architect` as its own wave on the `arena synthesizer` line (`deep`) to name the target shape, the module layout, types, and call graph as if built today, per **principle-foundational-thinking** and **principle-redesign-from-first-principles**.
3. **Wave 3, subtract then migrate.** Dispatch one `magic-agent` on `feature, refactoring` with the pinned contract, the target shape, and the file fence. It deletes dead code, collapses one-caller wrappers, drops redundant validators, and removes orphan references before introducing the new shape (**principle-subtract-before-you-add**). The smallest change that reaches the target shape ships (**principle-laziness-protocol**), and a speculative cleanup that "might help" gets reverted. For API reshapes, it migrates every caller and deletes the old API in the same wave (**principle-migrate-callers-then-delete-legacy-apis**), with no compatibility shims and no parallel old-and-new paths. Every rename is spot-checked against the actual files, because renames silently miss usages in strings, prose, and back-references.
4. **Wave 4, prove equivalence.** Dispatch `swarm workers` (default `main`) to prove behavior is unchanged on the real artifact, not "it compiles" (**principle-prove-it-works**). For larger reshapes it runs the equivalence check, a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface. A second `judgment and prose` (default `deep`) leaf confirms the change is worth keeping by naming where reader load dropped (**principle-minimize-reader-load**). If the diff does not lower reader load somewhere, revert it.
5. Rebase into small ordered commits. A subtraction commit, then the reshape, then any follow-on cleanup, each shaped with **principle-sequence-verifiable-units** so every behavior-preserving slice stays green before the next.
6. **Wave 5, open the PR.** Run **Opening a PR**, whose commit splitting, `/make-pr-easy-to-review`, PR body, and reply draft run in one `judgment and prose` (default `deep`) `magic-agent`.

**Reply.** Report the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped, and what got reverted. No new behavior.
