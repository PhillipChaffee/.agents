# Autonomous run

**You own the exit predicate.** This chat keeps the predicate, the loop, and the trail, and every heavy step is a flat depth-1 wave whose model comes from a role line in the `magic-models` role file.

1. **Wave 1, validate the predicate.** State the exit condition as a checkable predicate before the first iteration (tests green, repro fixed, all N PRs merged, pixel-diff zero). Dispatch one `magic-agent` on `judgment and prose` (default `deep`) to apply `take-a-step-back` to that predicate and confirm that satisfying it actually achieves the user's end-to-end goal. It returns the predicate with any gap named, and this chat adopts or narrows it.
2. **Pick the wake mechanism.** Use the harness's `/loop` command, a built-in rather than a magic skill. An event to watch (CI, a merge, a ref advancing) gets a watcher on the `fast, mechanical, miners` line (default `fast`) that wakes you on the event, with a long time-based heartbeat as fallback. No event gets a fixed-interval heartbeat sized to when the result is worth re-checking. Pick each subagent's reasoning level and fast or standard speed for the job, per the Subagents section.
3. **Iterate through a fresh leaf.** Each iteration dispatches one fresh `magic-agent` on `feature, refactoring`, `bug-fix`, or `hardest tasks`, whichever the unit needs, with the predicate, the evidence so far, and a file fence. It makes the smallest change the evidence justifies, verifies it against the predicate, commits if it advanced, and reports the result. This chat discards changes that did not help, and belt-and-suspenders that "might help" gets reverted rather than left to ride.
   Sequence the work via the **principle-sequence-verifiable-units** skill, verifying each unit before the next instead of batching checks at the end.
4. Mid-run discoveries that support the goal are yours. Address broken skills, related bugs, flaky verifiers, review noise, tooling failures, orphaned follow-ups, and fixable drift yourself via magic-mode. Put out-of-band fixes in their own PR, dispatched as a fresh depth-1 leaf, and never park reversible work for the human. Surface only irreversible actions, genuine product or preference calls no experiment can settle, or a real dead end. Keep the predicate as the main drive, and return to it after each side fix.
5. Checkpoint every iteration via the **show-me-your-work** skill, a row for what changed and whether the predicate moved.
6. Stop when the predicate is met. A plateau is not a stop, so keep going and pivot your approach to push past it. Surface a genuine dead end rather than spinning, and never relax the predicate to declare victory. If mid-run evidence shows the predicate is a flawed proxy that passes locally while leaving the user's actual production goal broken, apply `take-a-step-back` again and surface the mismatch at the top of your report instead of claiming the goal is solved.

**Reply.** State the exit condition, iterations run, what landed, what was discarded, and the final predicate state.
